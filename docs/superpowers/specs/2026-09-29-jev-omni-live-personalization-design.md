# JEV-OMNI 실시간 맞춤 UI 설계

**상태:** 사용자 설계 검토 대기

**범위:** 브라우저 로컬 신호에 따른 실시간 모듈 강조, 섹션 순서, 상세 수준 조정.

## 배경

현재 `app.js`의 JEV-OMNI는 방문 횟수, 카탈로그·맵 클릭, 선택 모델, 유입 경로, 전체 체류 시간을 `localStorage`에 기록한다. `trackOmni()`가 이벤트 직후 세그먼트를 계산하고, CSS는 세그먼트에 따라 일부 섹션을 강조한다. 하지만 CPU·GPU·Neural을 각각 탐색한 신호는 없고, 누적 횟수만으로 정한 `Returning`이 현재 세션의 관심보다 우선할 수 있다.

사용자는 자주 살펴보는 CPU·GPU·Neural 모듈 강조와 방문 목적에 따른 페이지 섹션 순서·상세 수준의 자동 조정을 승인했다.

## 목표와 제외 범위

- 사용자의 최근 행동에 즉시 반응해 관심 모듈을 강조한다.
- 탐색 목적이 분명해지면 주요 콘텐츠 섹션의 순서와 정보 밀도를 자동 조정한다.
- 브라우저 안에서만 판단하고 저장한다. 외부 분석 서비스, 서버 프로필, 생성형 AI 호출은 추가하지 않는다.
- 초기 화면 복귀와 맞춤 UI 끄기를 제공하고, 키보드·보조 기술 사용 중 포커스를 보존한다.
- 칩 사양이나 예시 점수의 의미는 새로 추론하거나 바꾸지 않는다.

## 추천 접근

명시적 선택을 강한 신호로, 충분한 화면 노출 시간을 약한 신호로 쓰는 규칙 기반 혼합 방식을 사용한다. 단순 세그먼트별 테마 변경은 만들지 않는다. 모듈 포커스는 즉시 반응시키고, 섹션 재배치에는 높은 확신을 요구한다.

## 신호와 의도 추정

### 신호

- 지식 맵의 CPU·GPU·Neural 행을 누른 행동은 해당 모듈의 강한 관심 신호다. 현재 행은 정적 표시이므로 명시적 모듈 선택 조작을 추가한다.
- 같은 모듈을 비교 화면에서 다시 선택한 행동은 보강 신호다.
- 특정 모듈 행이 화면에 충분히 노출된 시간은 약한 신호로만 반영한다. 화면에 잠깐 나타났거나 백그라운드 탭인 동안은 관심으로 계산하지 않는다.
- 카탈로그에서 칩을 연속 선택해 비교를 구성하면 비교 목적 신호다. 카탈로그·맵을 오가며 모델을 살피는 행동은 아키텍처 탐색 신호다.

### 점수

- 모듈 선택은 관심 점수 3점, 같은 모듈 비교 행 선택은 2점, 해당 모듈 행에 포인터를 둔 채 8초 이상 활성 탭에서 보는 행동은 1점으로 계산한다. 세션 점수는 10분 반감기로 약해진다.
- 비교 목적은 현재 기본 선택을 제외하고 사용자가 서로 다른 칩 두 개를 직접 고르면 확정한다. 아키텍처 목적은 같은 모듈 점수가 5점 이상일 때 확정한다. 그 외는 폭넓은 탐색으로 둔다.
- 세션 점수와 여러 방문에서 누적한 로컬 모듈 선호도를 분리한다. 기존 `visits`나 전체 누적 클릭 수만으로 `Returning`을 강제하지 않는다. 과거 프로필은 깨지지 않게 읽되, 새 의도 판단에 기존 누적 클릭을 그대로 쓰지 않는다.
- 여러 방문의 초기 모듈 강조는 명시적 선택 횟수로 정한다. 가장 많이 선택된 모듈이 다음 모듈보다 두 번 이상 앞설 때만 시작 시 강조하고, 과거 선호만으로 섹션 순서를 바꾸지는 않는다.
- 명시적 모듈 선택은 강조와 상세 패널을 즉시 갱신한다. 섹션 순서는 비교 목적 확정 또는 아키텍처 목적 확정 뒤에만 갱신한다. 한 번의 약한 신호로 섹션 순서를 바꾸지 않는다.
- 최근 의도가 불분명하거나 점수 차이가 작으면 현재 순서를 유지한다.

## 화면 반응

주요 콘텐츠 섹션은 `CHIP REGISTRY`, `KNOWLEDGE MAP`, `COMPARISON CONSOLE` 세 가지다. 맨 위의 세대 그래프와 페이지 진입점은 고정해 사이트의 기준점을 유지한다.

| 감지된 의도 | 주요 콘텐츠 순서 | 상세 표시 |
| --- | --- | --- |
| 비교 | 비교 콘솔 → 칩 목록 → 지식 맵 | 선택한 두 칩의 관련 모듈을 펼침 |
| 아키텍처 탐색 | 지식 맵 → 비교 콘솔 → 칩 목록 | 관심 CPU·GPU·Neural 행과 해당 지표를 펼침 |
| 폭넓은 탐색 또는 낮은 확신 | 칩 목록 → 지식 맵 → 비교 콘솔 | 모든 모듈의 기본 요약 표시 |

- 모듈 관심은 세대 그래프, 지식 맵, 비교 결과에서 동일하게 강조한다.
- 지식 맵의 모듈 행에 키보드로 선택 가능한 조작과 현재 포커스 상태 표시를 제공한다. 포인터 체류는 보조 신호이며, 터치·키보드 사용자는 명시적 선택으로 동일하게 개인화할 수 있다.
- 상세 수준은 현재 데이터에 이미 있는 모듈 값과 지표만 이용한다. 상세 뷰에도 `ILLUSTRATIVE INDEX`가 예시 비교값임을 표시하고, 실제 사양을 새로 생성하지 않는다.
- DOM 순서와 섹션 레일 순서를 함께 바꿔 화면 순서, 키보드 탐색, 접근성 트리 순서가 일치하도록 한다.
- 현재 읽는 섹션 안에 포커스가 있거나 사용자가 스크롤 중이면 재배치를 보류한다. 안전한 시점에 적용하고 현재 읽던 콘텐츠가 화면 밖으로 튀지 않도록 스크롤 위치를 보존한다.
- CSS 전환은 `prefers-reduced-motion`을 존중한다. 의도 변경은 짧은 상태 알림으로 안내한다.

## 저장과 사용자 제어

- 순간 의도는 현재 탭 범위의 상태로 둔다. 여러 방문에 걸친 선호는 기존 JEV 로컬 프로필에 CPU·GPU·Neural별 집계값으로만 보관한다.
- 기존 프로필을 읽을 수 있도록 필드 기본값을 제공한다. 손상되거나 차단된 저장소에서도 개인화 없는 기본 UI는 작동해야 한다.
- 맞춤 UI를 끄면 DOM 순서와 모듈 표시를 기본값으로 복구하고, 기존 로컬 프로필 삭제 버튼은 모든 프로필 기록을 계속 제거한다.
- 맞춤 UI 켜기/끄기를 사용자가 직접 조절할 수 있게 한다. 선택 상태는 브라우저에 보관하며, 끄면 새 신호를 수집하지 않고 기본 화면으로 복구한다.
- 유입 경로와 이용 기록은 계속 로컬에만 보관한다. 사용자 동의 없이 외부 전송 또는 기기 간 결합을 하지 않는다.

## 검증 기준

1. CPU·GPU·Neural 행을 선택하면 새로고침 없이 해당 모듈이 화면 영역 전반에서 강조되고, 상세 표시가 갱신된다.
2. 모듈 행을 짧게 스쳐 지나가는 것만으로 선호도가 확정되지 않는다. 반복되거나 명시적인 의도 신호가 있어야 섹션 순서가 달라진다.
3. 비교 목적에서는 비교 콘솔이, 아키텍처 목적에서는 지식 맵이 카탈로그보다 앞선다. 기본/낮은 확신에서는 기본 순서를 유지한다.
4. 섹션 재배치 시 섹션 레일과 DOM 순서가 일치하고, 활성 키보드 포커스와 읽던 위치를 보존한다.
5. 맞춤 UI 끄기 및 프로필 초기화 후 기본 순서와 요약 표시로 복귀한다.
6. 이전 프로필에서 `visits > 1`이라는 이유만으로 Returning UI가 강제되지 않고, 명시적 과거 모듈 선호만 시작 강조에 사용된다.
7. 4개 언어, 좁은 화면, `prefers-reduced-motion`, localStorage 차단·손상 데이터를 확인한다.
8. 의도 점수와 순서 선택은 작은 결정 로직으로 독립 검증한다. `npm test`, 프로덕션 빌드, `git diff --check`를 통과시킨다.

## 구현 전 검토 사항

- 설계 단계에서 추천한 기본 순서와 순간/누적 관심의 분리를 사용자가 확인한다.
- 이 문서 검토 및 승인 후에만 구현 계획과 코드 변경을 시작한다.
